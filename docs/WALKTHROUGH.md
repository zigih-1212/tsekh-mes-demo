# WALKTHROUGH — как устроен проект «Цех» (шпаргалка для собеседования)

## Зачем такая архитектура

Производство швейное: есть изделия (подушка, повязка…), у каждого — спецификация (BOM: сколько ткани,
микросфер на единицу) и маршрут (раскрой → пошив → вышивка → дозирование → ОТК → упаковка).
Нужно планировать заказы, выпускать их в цех, следить за заданиями opérateurs и принимать готовую продукцию.

## Backend (FastAPI, синхронный SQLAlchemy, SQLite)

- `app/main.py` — сборка приложения, CORS, `create_all` + seed при старте.
- `app/models.py` — доменные таблицы: User, Material, Product, BomItem, RoutingStep, ProductionOrder,
  WorkTask, StockMove, FinishedGoodsReceipt. Enum-статусы.
- `app/routers/orders.py` — главная бизнес-логика:
  - `release` — проверяет остатки по BOM×qty (иначе 409), списывает материалы (StockMove consumption),
    создаёт по WorkTask на каждую операцию маршрута со **snapshot ставки**;
  - `receive_fg` — приёмка ГП частями, заказ завершается когда принято всё;
  - `tasks assign/start/complete` — годные+брак ≤ задание, начисление = годные × rate.
- `app/routers/warehouse.py` — остатки (сумма знаковых движений), журнал, приход/списание/корректировка.
- `app/routers/analytics.py` — дашборд: статусы заказов, выпуск по дням, брак %, ФОТ по операторам, low stock.
- `app/deps.py` — JWT-аутентификация (OAuth2 password flow, username = email) и `require_roles(...)`.
- Почему sync SQLAlchemy: демо + SQLite, меньше бойлерплейта; в проде — async + PostgreSQL.
- Почему без Alembic: демо, `create_all` при старте; в проде Alembic (ADR-001).

## Frontend (React + TS + Vite)

- `src/api.ts` — axios-клиент, токен в localStorage, 401 → редирект на /login. Прокси `/api` → :8000 в vite.config.
- `src/auth.tsx` — AuthContext, login/logout.
- `src/App.tsx` — роуты и sidebar; пункты меню фильтруются по роли.
- Страницы: Login, Dashboard (recharts: pie по статусам, bar по дням, ФОТ, low stock),
  Orders (создание/выпуск/отмена), OrderDetail (операции, назначение, приёмка ГП),
  Tasks (мои/все, start/complete), Catalog + ProductEdit (редакторы BOM и маршрута),
  Warehouse (остатки, движения, ГП), Users (только admin).

## Типовой сценарий (покажите на демо)

1. Технолог создаёт заказ (изделие + qty) → статус planned.
2. Выпуск: система проверяет склад, списывает материалы, создаёт задания по маршруту.
3. Мастер назначает оператора; оператор начинает и завершает задание (годные/брак).
4. Кладовщик принимает ГП частями; заказ завершается.
5. Директор смотрит дашборд: выпуск, брак, ФОТ, дефицит материалов.

## На что обратить внимание на技術ическом интервью

- Почему snapshot ставки в WorkTask: иначе смена ставки ретроспективно меняет зарплату.
- Почему проверка остатков при release, а не при создании: план может ждать материалы.
- Почему consumption при release: материалы резервируются под заказ в момент выпуска.
- Почему SQLite/без Alembic в демо и что меняется в проде (PostgreSQL, миграции, Docker) — см. ADR-001.
- 409 вместо тихого успеха: фронт и API честно сообщают о конфликте бизнес-правил.
